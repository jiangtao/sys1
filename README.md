# System One Model 实践探索

探索 Laya、Jev、Kev 在国内中文任务中的适用场景和能力边界。先用游戏做可控对照：模型提出结构化选择，游戏规则决定能否执行。

## 游戏

### 贪吃蛇

Laya 与 Jev 在同一组十个 seed 上均 10/10 通关。Jev 总步数少 5.42%，后端整批耗时多 48.3%；它只在 6/10 个 seed 领先，尚不能认定稳定优势。

给定规划器安全候选后的已证最短原选率：Laya 99.47%，Jev 100%。这不是独立寻路正确率。[十种子数据](docs/results/snake-2026-09-23.md)

Kev-0.8B 随后完成独立十种子批次：10/10 通关、1,180 个能量点、22,105 步；3,776 次真实调用中 3,773 次为已证最短原选并被采纳，规划器纠正 3 次，请求延迟中位数 547.0 ms。当前 Kev 与历史 Laya/Jev 的引擎、应用和批次脚本快照不同，且 Kev 本地 MLX 与 Jev 远程服务的延迟不可作为模型纯速度排名。[Kev 十种子数据](docs/results/kev-0.8b-2026-09-24.md)

### 象棋

以 Pikafish 首选为参照，Laya 历史自对弈的 101 次非强制选择中，19 次与首选一致，29 次被守门采纳。

Kev 在相同的 101 个保存局面上 95 次选中首选。但题目明确标出了首选，这主要衡量遵循给定排序，不能当成棋力或真实对局采纳率。[象棋结果与口径](docs/results/xiangqi-2026-09-23.md)

候选由规划器提供，已证最短原选率不表示独立寻路。两个游戏都有规划器或引擎守门；当前没有三模型同代码、同条件的完整游戏排名。

## UI 交互
