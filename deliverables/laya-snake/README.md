# Laya Snake Lab

实时二维贪吃蛇。界面只保留棋盘、资源和决策日志。默认使用 Laya 提议、规划器校验与兜底的控制方式，提供 10 个逐渐拥挤的关卡。目标优先级固定为：**存活 > 最短路径 > 多吃能量**。

## 启动

```sh
cd deliverables/laya-snake
./start.sh
```

打开 <http://127.0.0.1:8766>，页面会自动开始。脚本复用已就绪的 `127.0.0.1:8765` Laya 服务；未启动时自动加载相邻 `laya-zh/model/` 下的模型。使用 `laya-zh/.venv` 中已有 Python 和依赖，无需安装前端依赖或访问 CDN。

页面“决策模型”可切换 Laya / TypeSafe Jev / 本地 Kev-0.8B。切换时以**同一个 seed** 重新开局，三种模型共用 10 关难度、游戏规则、规划器及其开关、候选方向和问题说明。Jev 使用 [TypeSafe System One API](https://docs.typesafe.ai/introduction/quickstart) 的 `jev-latest`；本机将 `TYPESAFE_API_KEY` 作为进程环境变量提供，或把密钥保存到仓库外的 `~/.config/jev-snake/typesafe_api_key`（权限 `600`）。密钥不进入游戏请求、日志或仓库。未配置时 Jev 新局会拒绝启动，避免把纯规划器结果误当 Jev 表现。

Kev 绑定同级目录 `../kev` 已启动的本地服务 `http://127.0.0.1:8009`，请求固定使用 `POST /v1/systemone` 和 `model=kev-latest`，不发送密钥。新局前的 `/api/health?model=kev` 会真实读取 Kev 的 `/v1/models`，并要求 `models[0]` 是 `kev-latest` 且 `run` 以 `jaredpalmer/kev-0.8b@` 开头；服务未加载 Kev-0.8B 时不会创建游戏。也可用 `../kev/control.sh status` 检查服务。

同配置整局复测入口为 `../laya-zh/.venv/bin/python verification/compare_models.py --seed 820498657 --model both`。原始逐步日志和摘要写入 `verification/model_comparison/`。报告区分模型真实调用、规划器确定步与兜底；模型请求失败即停止该次复测。Jev 与 Laya 用各自 tokenizer 返回的 token 数，数值不能直接当作等价算力或费用；两者的游戏输入仍受同一份 Laya 1024-token 预检约束。Jev 的远程调用时间包含网络延迟，Laya 在本机运行；性能结论据实标注环境差异。

种子 `820498657` 的真实对照见 [Laya / Jev 同配置结果](verification/model_comparison/RESULTS.md)：均十关通关，Laya 2124 步、Jev 2234 步；Jev 单步已证最短命中率更高，但整局多走 110 步，且远程请求和重试带来明显耗时。

固定十个新种子的配对对照见 [十局实验报告](verification/model_comparison/paired_20260923_v2/RESULTS.md)：两方均 10/10 通关；Jev 合计少走 1184 步（5.42%），后端总耗时多 48.3%。实验使用持久 HTTP 连接的 Jev 客户端；旧逐次建连的 TLS 中断结果另存为诊断批次，没有混入正式对照。

可用 `http://127.0.0.1:8766/?seed=2041590040` 固定种子重放。种子不提供给模型预测未来食物。

终端按 `Ctrl+C` 停止本次脚本启动的服务。脚本不会停止原先已运行的 Laya 服务。两项服务仅绑定本机回环地址，不发布到公网。

## 玩法与决策

- 默认以“极速”自动运行，取消人为播放等待。Laya 局只有唯一物理安全方向时由规划器直接执行；多个安全方向仍调用模型、记录原始选择，再由规划器校验最短与兜底。可选的 `skip_deterministic_model=True` 会在唯一已证最短方向时跳过模型，但两种子实跑未改善总步数，不作为 Laya 默认。所有跳过步均标为 `modelCalled=false`，不将规划器决定算作模型正确。也可切换 1×/2×/4×/8×，暂停、单步或重新开始。暂停时已经发出的步骤仍会完成。
- 10 关逐步收缩棋盘、增加初始蛇长和能量目标，同时缩短最小播放间隔。实际移动间隔还包括模型推理耗时，播放倍率不会让模型本身推理加速。
- 规划器负责精确寻路、完整蛇体复验、碰撞与存活边界、路径长度校验和兜底。以原有 Hamiltonian 安全环为基线；每颗食物开始时，若普通动态搜索找出更短路线，再搜索能支持当前蛇体及整条路线的新安全环。只有全格覆盖、闭环相邻、每步及进食增长独立复验通过，才切换并直接缓存该路线。无证书或预算耗尽时保留旧路线。
- 安全环固定且到当前食物前不增长时，头部只会沿环序向食物前进；搜索把后续行为相同的完整蛇体合并成 `(head, elapsed)`，结合初始尾部释放时间作精确转移。启发距离来自忽略蛇身的单向网格图，包含所有真实合法移动；最终仍用原有完整蛇体转移逐步复验，包含尾格腾空及进食增长。压缩只适用于初始环序合法、食物不占蛇身且蛇长至少为 2 的局面，其他输入保留完整状态搜索；未提高 12000 节点预算，也没有放松安全约束。
- 新食物规划时搜索安全捷径；执行缓存途中，如果食物与头部同轴、直线物理可行且严格短于缓存，可额外重查安全证书。每颗食物最多重查 4 次，每次 2000 个证书搜索节点。只有独立校验通过才同步替换环和缓存；失败继续原路线。一次切换和第一步执行原子提交，异常恢复蛇体、环、缓存、重试计数、资源、随机状态和日志。食物始终按固定规范顺序抽取空格，不因活动环重排而改变采样规则。
- 普通 A* 已证明的更短路线若通过证书校验，本颗目标同时达到物理最短；其余路线的最短结论限于当前安全环。两者都不代表随机未来食物下的整局全局最短。
- Laya 比较完整候选路线：先满足存活约束，再选最短路径，前两项相当时才考虑更多能量。执行层只采纳通过校验的最佳或等长提议；更差、无法证明或无效的提议采用已经验证的规划器路线。模型不可用时也明确记录原因和规划器接管，不伪装成模型成功。
- 本地 Laya 的置信度计算至少需要两个选项；只有一个物理安全方向时直接由规划器执行，不调用模型。侧栏“Laya 改选”统计它实际改走另一条同长路线的次数，不是模型正确率；原始提议是否最短应从日志候选成本独立计算。可选跳过策略启用后的调用口径与默认全候选口径不可直接比较。仅历史回放接口保留同义标签兼容。
- Laya 的输入保留完整棋盘、头到尾的蛇身顺序、完整候选路线和风险指标。紧凑编码保留空间信息，未知路线仍标为未知。候选范围和路线参考来自规划器，不能把它们算成 Laya 独立搜索的能力；处罚和近期反馈不等于在线训练。

侧栏默认显示“每步记录”，分别展示模型建议、实际执行和规划器兜底。规划器保留当前食物的完整路线缓存，每步只接受同样短且安全的分支，剩余步数持续减少，避免模型不断改道兜圈。进食、换关或缓存失效时重新规划。每条日志包含 `model`、`modelCalled` 和 `modelCallStatus`（`skipped` / `succeeded` / `failed`）；Kev 请求失败保留 `modelError` 并明确记录为 Kev 失败与规划器接管，规划器确定步不会计作 Kev 成功调用。

日志详情包含原始请求和响应、模型置信度（若有）、推理耗时、候选计划、模型错误、实际选择及资源变化。中文说明由规则引擎根据局面生成，**不是 Laya 输出的思维过程**。模型原始命中率、规划器兜底次数和最终收集量分别统计，通关不等于模型每次选对。可导出完整 JSON；侧栏仅渲染筛选结果的最近 150 条。

模型使用中性方案编号（`A`、`B`、`C`），通过 `choiceMap` 映射为安全候选方向，每步继续轮换编号。全部候选成本已证明时，单次调用明确说明安全校验已完成，先比较到食物的步数，不能为更多出口增加步数；完整棋盘、蛇身与风险信息仍保留在上下文。描述使用固定样本验证过的简洁英文，网页战报仍为中文；没有修改权重，也没有把规划器答案冒充模型输出。未知成本和实验性前瞻保留原规则。

`modelChoice` 是原始编号，`chosen` 是原始提议，`executed` 是实际方向。`executionSource` 区分 `laya`、`jev`、`kev`、`planner_fallback`、`planner_forced`；唯一方向的 `raw/request/modelChoice/contextAudit` 均为空。`routeOverride/overrideKind` 说明兜底，`modelError` 保留模型失败原因。Kev 的 `contextAudit.tokenMatch` 固定为 `null`：本地预检使用 Laya tokenizer 估算，Kev 的真实 `usage.input_tokens` 只记录供核对，不与不同 tokenizer 的计数强行比较；Kev 使用本地服务的 16,384 token 上限，Laya/Jev 继续沿用既有 1,024 token 预检。`planning.cycleOptimization` 记录旧路线、新路线、完整安全环证书及本颗节省步数，`trigger` 区分 `initial_food` 与 `mid_route_straight`，后者保留 `FOLLOW_ROUTE` 阶段并记录次数和预算，收益归于规划器。历史自由决策仅保留为内部回放入口。

每步日志可单独展开模型输入。`contextAudit` 记录棋盘、蛇身与已知路线的完整度、近期动作数量和输入 token 数；预算包含问题和选项。蛇身用头坐标和方向链无损表示，同时保留最近 8 步和上一轮实际执行路线。CTX3 进一步用方向计数压缩完整路线、用方案引用去除重复路径，并合并历史列；完整棋盘、坐标朝向和风险指标不删除。只有实际 tokenizer 测得更省时才采用 CTX3，否则保留 CTX2。审计先无损展开再检查路线，记录 `uncompressedInputTokens` / `savedInputTokens`；网页显示节省量。超出 1024 tokens、编码不完整或实际 token 数对不上时，该次模型判断作废并记录错误，采用验证过的规划器路线，不将截断输入算作成功决策。

完整上下文修复了过去只提供蛇长和前六步路线的信息缺口，不等于模型已学会稳定规划或保证最优。

## 目标、状态机与处罚

默认 `controller=guarded`，`objectivePriority=[survival, shortest_path, energy]`，安全捷径证书开启，实验性两颗食物均值前瞻关闭。存活第一，再优化当前食物步数，前两项相当才比较能量收益。搜索考虑完整蛇体、移动尾巴和进食增长；未完成证明时沿已验证路线前进，不将未知当作不安全或最优。

按“规划 → Laya 提议 → 校验或兜底 → 执行一格并更新缓存”循环。进食或换关更新目标；最终进入 `DONE`，生命归零进入 `LOST`。模型失败但有验证过的安全路线时继续，由日志明确标注规划器执行。

| 事件 | 生命 | 能量 |
| --- | --- | --- |
| 新游戏 | 100 | 100 |
| 实际执行的已证无收益绕路，或重复完整局面 | −5 | −10 |
| 模型错误提议已被规划器纠正 | 0 | 0 |
| 存活时吃到食物 | +3 | +12 |
| 存活时通过非最终关卡 | +15 | +25 |

数值限制在 0–100。处罚按实际执行结算，已经纠正的模型提议只记错误，不扣血；必要的安全回退和未知最优性不罚。正常的前置校验应阻止无效绕路，同一步最多处罚一次。生命归零不会被同一步奖励复活；能量归零不单独判负。每关最后一颗食物立即切换棋盘。

## 本地检查

Laya 路径优先的当前默认及两种子完整实跑见 [选项偏好与中途直线捷径优化](verification/DECISION_V2_RESULTS.md)：合计4217步。之后的 [确定步跳过模型实验](verification/UNIQUE_SHORTEST_RESULTS.md)减少模型请求但合计多11步；进一步 [删除执行来源标签实验](verification/ROUTE_PRIORITY_AUDIT.md)合计4403步。两项实验均有完整日志，未作为默认。更早的 [输入压缩评测](verification/COMPRESSION_OPTIMIZATION.md)保留作历史基线。

```sh
../laya-zh/.venv/bin/python -m unittest test_engine.py test_certified_routes.py test_future_planner.py test_planner_bounds.py test_context_codec.py test_midroute_shortcuts.py test_unique_shortest.py test_kev_api.py
node --check web/app.js
```

引擎测试不依赖模型；真实模型集成需要启动服务后调用 `/api/game` 和 `/api/game/{id}/step`。前端静态资源位于 `web/`；后端 `app.py` 通过 `/api/` 代理模型，`engine.py` 管理关卡、游戏规则和安全候选。

初版使用隔离的 headless Chromium 检查了自动运行、暂停、单步、原始输出展开、倍率、事件筛选、日志导出和重开；390px 窄屏无横向溢出，未发现脚本错误。`preview-desktop.png`、`preview-mobile.png` 是初版截图。当前精简版通过用户正在使用的 Codex 内置浏览器验证，不能将该结果称为真实 Chrome 验收。

历史五关版真实 HTTP 集成实测：seed `20260922`，Laya 在 MPS 上完成 5/5 关，共 579 步、40 个能量点，日志无截断，耗时 35.26 秒（不包含网页动画等待）。见 [历史验证证据](verification/full_game_http_evidence.json)。当前复现脚本为 [full_game_http.py](verification/full_game_http.py)。

修正前十关版实测为 2738 步；86 段吃食路线仅 15 段达到环序约束内最短。完整记录、逐段 A* 对比、短蛇和长蛇反例见 [路径与状态机分析](verification/ROUTE_ANALYSIS.md)。该文件保留基线，不用改道后的结果冒充模型原始能力。

历史中性推荐方案版曾实测通关 10 关、1074 步，并有 13 次引擎纠正。见 [旧版验证证据](verification/fsm_http_evidence.json) 与 [旧版运行日志](verification/fsm_decisions.json)。旧关卡和旧输入的 95.9% 不适用于当前版本，不能混用。

上一版摘要输入的 30 步实测使用 372–732 tokens，有 7 次头部回访、0 次完整局面重复，最终生命40。见 [摘要输入运行记录](verification/strategy_runtime_smoke.json)。

此前候选表达实验虽然减少了兜底，却用了1978步，原版为1914步，未证明整局路径改善，未启用。见 [候选表达实验记录](verification/CHOICE_OPTIMIZATION.md)。

当前安全捷径版本通过41项检查和三种子完整 HTTP 回归：1914→1668步、1731→1588步、1918→1716步，均十关通关、118个能量、生命/能量100；合计少591步（10.62%）。同版纯规划器固定取参考路线为5511步，加入Laya的同长方案选择为4972步。唯一方向不再调用模型，原始提议与兜底继续分开记录。详见 [路径改进与职责对照](verification/CERTIFIED_PATH_RESULTS.md)。

补充作用验证：同一种子重跑Laya仍为1668步，固定参考1909步，简单出口/空间规则1782步；5次随机同长路线的中位数1647步。所有策略都满血通关，因此目前不能宣称Laya提高了成功率，也未证明优于随机平局选择。见 [完整消融与调用归属](verification/LAYA_CONTRIBUTION.md)。
