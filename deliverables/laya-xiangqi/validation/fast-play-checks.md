# 极速模式验收

2026-09-22，本机 MPS Laya 与 Pikafish。

## 改动

- 网页与 API 默认搜索时限为 0.3 秒，允许 0.1—30 秒；默认保留 5 个真实候选。
- 取消自对弈两步之间的 650ms 额外停顿。
- Laya 输入仅保留 FEN、执棋方、合法着数量、候选评分和前三步变化；日志中的完整 PV、候选及 UCI 输出不裁剪。
- 默认决策树视图不构建隐藏日志；原始响应按需展开，关闭的残局弹窗不再每步重绘。
- 每步日志提供 `searchMs`、`layaMs` 和 `totalMs`，便于继续定位耗时。

## 实测

相同残局初始局面的旧版 2 秒搜索，两次 API 请求分别耗时 2290.5ms、2307.6ms，Laya 输入均为 1024 token。

新版同局面 0.3 秒搜索，两次请求分别耗时 2972.9ms、544.7ms，输入为 487、484 token。第一步的额外耗时在 Laya 调用阶段（2652ms），第二步模型调用 224ms；首步仍可能较慢，不能将稳定吞吐理解为每一步的时延保证。

独立 Headless Chrome 完成 7 个真实 Laya 半回合。第一步搜索加模型约 1387ms；后续六步响应间隔为 457、424、513、480、438、483ms，均值约 **466ms/手**。每一步都有模型请求 ID、5 个候选及完整 PV。用户真实 Chrome Profile 未作为本次验收环境。

暂停后没有再发起后续决策；日志切换、原始响应按需展开、残局弹窗正常；浏览器无 JavaScript 异常。18 个单元测试通过，NaN、Infinity、布尔值时间参数返回 400 且不改棋局。现有棋局从存档恢复。

更短的搜索可能减少分析深度，需更深入的战术判断时可切回 2、8、15 秒档位。
