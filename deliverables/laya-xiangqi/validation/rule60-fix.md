# Rule60 边界与引擎故障修复

2026-09-22，棋局 `52ddc540ea2b478fbc13ec9ec701a6e2` 在第 149 个半回合 `c4a2` 后出现 perft 输出提前结束。

## 根因与复现

目标 FEN 为 `4ka1R1/9/9/9/8p/3c2P2/5r2P/B3BA3/4A4/4K4 b - - 120 109`。官方 Pikafish 对计数 120 输出 `CRITICAL ERROR ... Rule60 counter out of range`，退出码 1。通过完整 149 手历史重放后再查询也会拒绝，因此不是棋盘文本损坏。

测试副本仅把计数改为 119 或 0 时，都得到相同的 31 个合法着法。旧程序先查询合法着法、再做终局判断，在计数边界触发引擎拒绝；同时落子已更新而终局刷新失败，留下了 `playing` 的半提交状态。

## 修复

- 合法走法与将军检查仅对临时查询 FEN 使用 119 上限；真实 FEN、历史和裁决仍使用 120。
- 无合法着法判负、长将责任优先于无进展和棋；达到无进展上限后明确拒绝继续搜索。
- 合并原生 stdout/stderr，读取退出前剩余输出，保留命令、退出码和错误原因。同一引擎对象下一次合法查询可以重新启动。
- 人类落子、AI 落子和悔棋刷新失败会回滚棋局；失败单独记入系统日志，避免虚构已完成的走法。
- HTTP 错误包含当前棋局，前端同步版本并显示诊断；失败事件不计作成功的 Laya 决策。

## 验证
